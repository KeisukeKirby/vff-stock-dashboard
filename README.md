# VFF 在庫・発注ダッシュボード

Vibram FiveFingers(VFF)シューズの月末在庫と販売実績を突き合わせ、**サイズ・カラー単位の在庫推移予測**と**発注アラート**を出す静的ダッシュボードです。

- 在庫: 月末の `VFF Stock <dd-mm-yy>.xlsx`(Balance 列 = 輸入累計 − 販売累計)
- 販売実績: [sales-1st-half-26-dashboard](https://github.com/keisukekirby/sales-1st-half-26-dashboard) の `data/dashboard_data.json`(`vff_shoes.model_monthly` ほか)。この数値を販売実績の正とする

## 構成

| パス | 役割 |
|---|---|
| `index.html` | 完成したダッシュボード(生成物。データ埋め込み済みの単一ファイル、外部ライブラリなし) |
| `src/template.html` | ダッシュボード本体のテンプレート。`/*__DATA__*/null` に build.py がデータを埋め込む |
| `scripts/extract_stock.py` | xlsx → `data/stock.json`(標準ライブラリのみ、SKU=モデル×性別×カラー×サイズ) |
| `scripts/fetch_sales.py` | 販売ダッシュボードの JSON から VFF シューズ部分を `data/sales_vff.json` へ |
| `scripts/build.py` | 2つの JSON をテンプレートに埋め込んで `index.html` を生成。6月の輸出分のモデル別推定もここで計算 |

## 画面

上部の **前提条件バー** で、販売ペースの基準期間(直近3ヶ月 / 6ヶ月 / 2026年1〜8月)、6月の輸出除外、発注リードタイム、入荷予定の到着月を切り替えると全タブが再計算されます。

- **サマリー** — KPI(総在庫・月間ペース・在庫月数・欠品/要発注SKU・入荷予定)、至急対応アイテム(サイズ別セル)、モデル別在庫月数、全体在庫の12ヶ月推移予測
- **発注アラート** — ステータス(欠品中 / 要発注 / サイズ欠け / 注意 / 適正 / 過剰 / 滞留 / 入荷待ち)で絞り込めるアイテム×サイズのカード、SKU一覧表、CSV書き出し
- **在庫推移予測** — アイテムを選んで在庫推移、モデルの月次販売実績(2025年同月比較・輸出推定)、サイズ×月の月末在庫予測表
- **サイズ・カラー** — 性別×サイズの販売構成比 vs 在庫構成比、モデル内カラー構成の販売 vs 在庫
- **このデータについて** — ソース、計算方法、在庫表と JSON の突合表、制約、更新手順

## 計算方法(要点)

1. モデル別の月間販売ペース = 販売実績 JSON のモデル別月次足数を基準期間で平均
2. 2026-06 の一括輸出 948 足は在庫表の販売列に含まれないため、両者の差(50足以上のモデル)を輸出分として推定し、チェック ON で除外
3. SKU への配分 = 在庫表の SKU 別 2026 年販売 ÷ 2026 年の販売可能月数 を重みに、モデルのペースを比例配分(JSON にモデル×カラー×サイズの同時集計が無いため)
4. 在庫月数 = 在庫 ÷ ペース。リードタイム未満なら「要発注」、在庫0でペースありなら「欠品中」、12ヶ月超は「過剰」
5. 推移予測 = 前月末在庫 − ペース(0で打ち止め)。入荷予定は到着月を指定した月の頭に加算

## 更新手順

```bash
python scripts/extract_stock.py "C:\path\to\VFF Stock 30-09-26.xlsx"
python scripts/fetch_sales.py "C:\path\to\dashboard_data.json" <commit>
python scripts/build.py
```

`index.html` を main に push すると Vercel が自動デプロイします。ローカル確認は `python -m http.server 8765`。

> 元の xlsx(輸入インボイス番号を含む)はリポジトリに含めていません(`.gitignore`)。
